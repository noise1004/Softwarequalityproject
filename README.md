# SDV Pipeline — Iteration 1

A Software-Defined Vehicle (SDV) data pipeline using Eclipse Kuksa, Eclipse Zenoh, Eclipse Ditto, and Eclipse OpenSOVD. Vehicle OBD telemetry is generated by a Python simulator, published to Kuksa, forwarded to Eclipse Ditto via a bridge script, and monitored for faults by OpenSOVD.

---

## Architecture Overview

```
send_obd_data_to_kuksa.py  (Vehicle Simulator)
        │  gRPC set_current_values
        ▼
Eclipse Kuksa Databroker  ◄── fault_injector.py (★ modification)
        │  gRPC get_current_values
        ▼
send_obd_data_to_ditto.py  (Kuksa–Ditto Bridge)
        │  HTTP PUT /api/2/things/
        ▼
Eclipse Ditto  (Digital Twin: org.vehicle:my-device)
        │
        ├──► Ditto UI  (http://localhost:8080)
        └──► OpenSOVD  diagnostic_monitor.py → DTC Report
```

**Signals:**
- `Vehicle.OBD.VehicleSpeed`
- `Vehicle.OBD.EngineSpeed`
- `Vehicle.OBD.ThrottlePosition`
- `Vehicle.OBD.CoolantTemperature`

**Functional modification:** Simulated engine over-temperature fault via Kuksa `set_target_values`

## Running the System

### Step 1 — Start the vehicle simulator
Open a terminal in the `kuksa-ditto/` folder:
```bash
python3 send_obd_data_to_kuksa.py
```
This publishes VehicleSpeed, EngineSpeed, ThrottlePosition, and CoolantTemperature to Kuksa every second.

### Step 2 — Start the Kuksa–Ditto bridge
Open a second terminal in the `kuksa-ditto/` folder:
```bash
python3 send_obd_data_to_ditto.py
```
This reads values from Kuksa and forwards them to Eclipse Ditto via HTTP PUT.

### Step 3 — Start the OpenSOVD diagnostic monitor
Open a third terminal in the `opensovd/` folder:
```bash
python3 diagnostic_monitor.py
```
OpenSOVD polls Ditto every 2 seconds and prints any active DTCs.

### Step 4 — Verify data is flowing
```bash
curl -u ditto:ditto http://localhost:8080/api/2/things/org.vehicle:my-device
```

Expected response:
```json
{
  "thingId": "org.vehicle:my-device",
  "policyId": "org.ovin:my-policy",
  "features": {
    "VehicleSpeed":        { "properties": { "value": 142.0 } },
    "EngineSpeed":         { "properties": { "value": 830.0 } },
    "ThrottlePosition":    { "properties": { "value": 67.0  } },
    "CoolantTemperature":  { "properties": { "value": 88.0  } }
  }
}
```

## Reproducing the Fault Injection (★ Functional Modification)

With the simulator and bridge already running, open a fourth terminal:
```bash
python3 kuksa-ditto/fault_injector.py
```

This overrides Vehicle.OBD.CoolantTemperature to 130°C via Kuksa's set_target_values API.

**What you should see:**

1. The CoolantTemperature feature in Ditto updates to 130
2. OpenSOVD prints:
   ```
   [DTC ACTIVE] P0217 — Engine Over-Temperature Condition
   ```
3. Stop fault_injector.py with Ctrl+C
4. The simulator restores a normal value on its next cycle
5. OpenSOVD prints:
   ```
   [DTC CLEARED] P0217 — Engine Over-Temperature Condition
   ```

## Functional Modification — Where the Change Lives

| Layer | File | Change |
|-------|------|--------|
| Kuksa | `kuksa-ditto/fault_injector.py` | Calls set_target_values(Vehicle.OBD.CoolantTemperature, 130) |
| Ditto | `kuksa-ditto/send_obd_data_to_ditto.py` | Bridge picks up injected value on next poll and PUTs to Ditto |
| OpenSOVD | `opensovd/diagnostic_monitor.py` | Detects CoolantTemperature > 120 → raises DTC P0217 |
